# Pata

Dispatch triage for couriers. Pata reads a raw customer address plus order context and returns a decision before the van leaves: `DELIVERABLE`, `CALL_FIRST`, or `LIKELY_FAIL`, with normalised fields, a one-line driver note, and the reason.

Entry for the DEV Hacktoberfest Open-Source AI Challenge, Week 2: Side Hustle. Built by Abdul Wasih (@iamwasih).

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/AbdulWasih05/pata)

Live demo: **https://pata-gw9g.onrender.com** (free instance; the first request after a quiet spell can take up to a minute). Serving checkpoint: run 2 (see [train/RUNS.md](train/RUNS.md), [eval/results.md](eval/results.md)).

## How it works

```
 browser / CSV / CLI
        |
        v
 FastAPI gateway (Render)  ---- Sentry agent trace per request
   1. rules_prelabel   pata/rules.py, always computed
   2. chat             tuned Qwen3.5-4B, Tinker OpenAI-compatible endpoint
                       (hedged: a 2nd request after 1.5 s, first answer wins)
   3. schema.validate  pata/schema.py (pydantic)
   4. rules_fallback   only if the model call fails or its JSON is invalid
        |
        v
 decision + normalised fields + driver note + call script
```

* `pata/schema.py`: the output contract. Rules, prompt, eval and API all import it.
* `pata/rules.py`: deterministic rules, pure functions with tests. They label the training data and are the serve-time fallback.
* `pata/prompt.py`: one fixed system prompt for training, eval and serving.
* `pata/service.py`: the agent loop and its Sentry spans. Addresses are customer PII, so prompt text is only sent to Sentry when `SENTRY_SEND_PROMPTS=1`.
* `train/`: LoRA SFT of `Qwen/Qwen3.5-4B` on Tinker with the `tinker_cookbook` supervised recipe, thinking disabled. Every run is logged in [train/RUNS.md](train/RUNS.md).
* `eval/run_eval.py`: base vs tuned vs rules per market. Results in [eval/results.md](eval/results.md).
* `pata/client.py`: OpenAI-compatible client. Tinker by default; any vLLM server works (`deploy/do_vllm.md`).
* `render.yaml`: the one-click Render blueprint.

## Run

```
uv sync --all-groups
uv run pytest
uv run ruff check .

# data (India from Hugging Face, UAE synthetic), then silver labels and splits
uv run python -m data.fetch_in --n 4000
uv run python -m data.ae_generator --n 3500 --seed 7 --out data/ae/ae_raw.jsonl
uv run python -m data.label

# gateway + UI on http://127.0.0.1:8000 (rules only unless MODEL_URL is set)
uv run uvicorn api.main:app --reload

# CLI
uv run pata triage --market AE --in orders.csv --out triaged.csv
```

Training and Tinker-based eval need Linux (`tinker_cookbook` depends on `tml-renderers`, which has no Windows wheel). On Windows, run them in WSL:

```
uv run python -m train.build_jsonl
uv run --env-file .env python -m train.train_tinker --run-name run1
uv run --env-file .env python -m eval.run_eval --checkpoint base
uv run --env-file .env python -m eval.run_eval --checkpoint tinker://<run>/sampler_weights/<step>
uv run python -m eval.run_eval --checkpoint rules
```

Secrets live in `.env` (see `.env.example`), never in the repo.

Split sizes and class balance: [data/splits/STATS.md](data/splits/STATS.md).

## Data provenance

* India, real: MCA company-registry addresses from [gagan1985/indian-addresses-gold](https://huggingface.co/datasets/gagan1985/indian-addresses-gold) and [gagan1985/indian-addresses-raw](https://huggingface.co/datasets/gagan1985/indian-addresses-raw) (Apache 2.0). Only `mca` rows are used; the `bank` rows are customer KYC data and are excluded.
* India, synthetic customer-typed: [abr-6024/indian-address-parsing-synthetic](https://huggingface.co/datasets/abr-6024/indian-address-parsing-synthetic) (Apache 2.0).
* UAE: **synthetic**, generated by `data/ae_generator.py` from real-world Gulf address patterns. No real customer addresses are in this repo.
* Base model: [Qwen/Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B), Apache 2.0. The LoRA adapter and merged weights are released under the same licence.
* Training labels are silver (from `pata/rules.py`). Reported test numbers come from `data/gold/`: 150 rows per market labelled by a blind LLM review (a Claude agent that saw the address, the order context and the decision definitions in BRIEF.md and DECISIONS.md, but never the rules' answer), not by humans. The sheet was sampled 50/50/50 by the rules' decision. See DECISIONS.md D16.

## Deploy your own (Render)

The button above creates one free web service from [`render.yaml`](render.yaml). Render asks for two values:

* `TINKER_API_KEY`: calls the tuned model on Tinker. Leave it empty and Pata runs on the rules alone. `PATA_MODEL` points at our run 2 checkpoint; set it to your own sampler path if your key cannot read ours.
* `SENTRY_DSN` (optional): turns on agent tracing.

To serve the merged weights yourself instead, run vLLM (`deploy/do_vllm.md`) and set `MODEL_URL=http://<host>:8000/v1` and `MODEL_API_KEY`.

The free instance sleeps when idle. Point an uptime monitor at `/healthz` every 5 minutes to keep it warm.

## What has been measured

All from `eval/results.md` (generated by `eval/run_eval.py`) and DECISIONS.md D18.

* Gold test sets, 150 rows per market, blind LLM review: tuned 4B decision accuracy 86.0% India, 85.3% UAE; base 4B 43.3% and 25.3%. Tuned answers were valid JSON 300 of 300 times.
* India field extraction: tuned 4B gets the building right 90.0% of the time and the area 87.3%; the rules get 47.3% and 14.0%.
* Latency, 40 sequential requests through the serving path (`eval/latency.md`, from `eval/latency_bench.py`): hedging cut p90 from 6.19 s to 2.92 s and requests over 5 s from 10 to 0.
* Cost: $1.62 per 10,000 parcels at Tinker's published sampling rates (`eval/latency.md`).

## Privacy

* Sentry spans carry lengths, decisions, token counts and flags, never the address, unless `SENTRY_SEND_PROMPTS=1`.
* `send_default_pii` is off. Uploaded CSVs are processed in memory and not stored.
* Addresses are sent to the model host (Tinker). Serve the merged weights on your own vLLM box to keep them in-house.
