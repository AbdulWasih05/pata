Know which parcels will fail before the van leaves.

Paste an address the way the customer typed it. A small fine-tuned model reads it like a dispatcher would and tells you to ship, call first, or hold.

00How to use this page3 steps

  1. 01 PASTEA delivery address, exactly as the customer wrote it. Landmarks and typos are fine.
  2. 02 SET CONTEXTMarket, cash on delivery or prepaid, and whether the order has a phone number.
  3. 03 READOne of three decisions, the reasons, a note for the driver, and the address split into parts.
DecisionMeaningDispatcher action
DeliverableA driver can find this.Load it.
Call firstFindable only with the customer's help.Phone using the script, then load.
Likely to failWrong or undeliverable as written.Hold the parcel.

04How it worksPer request

address + order context
  │
  ├─ 1. rules        written dispatcher rules give a first answer
  ├─ 2. model        fine-tuned Qwen3.5-4B reads the address
  ├─ 3. schema check reply must be valid JSON in the agreed format
  │
  └─ decision     model answer, or the rules answer if 2 or 3 fails
Model
Qwen3.5-4B, LoRA fine-tuned on Tinker (open weights, Apache 2.0)
Accuracy
86% India, 85% UAE on 150 held-out addresses each
Reads fields
Finds the building in 90% of Indian addresses, against 47% for rules alone
Speed
About 1 s per address; slow calls are re-sent after 1.5 s
Privacy
Addresses are not stored. Traces keep lengths and decisions, not the text.
Limits
UAE training data is synthetic. No map lookup, so it cannot tell if a building exists.
Qwen3.5-4B, LoRA fine-tuned on Tinker, with a rules fallback. UAE training data is synthetic.
